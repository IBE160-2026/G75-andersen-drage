### Diff-scope review (bmad-review: adversarial, edge-case-hunter, verification-gap)

Run over `4ce8814^..513bd0b` restricted to `web/ proxy/ e2e/` (lockfiles, recordings and Fixture JSON excluded), one subagent per lens, weighted to the story seams. Each finding below was re-checked against the source; lens names in brackets, overlap noted.

**R1 — Demo Mode sends an own Note's full text to the Proxy without Consent.** [adversarial + edge-case] `web/core/gate.ts:14-15` returns ok for `mode === "demo"` before it checks Consent; `web/api/studySet.ts:104` always sends all Passages. A student who declined Consent lands on Demovelger (Demo on), then drops an own file: the text goes to the local Proxy, which answers 404 `err.demoOnly`. It never reaches OpenRouter, and the Proxy keeps nothing (1.7), so FR-5 ("not sent to the provider") holds; but the gate order and D-16 were written without this case in view. Story seam: 1.3 Consent × 1.10 gate × 1.14 Demo. *Disposition: defer (decide). Cheapest guard: in demo mode send `passages: []` or check the hash against the sample manifest first. Prevention: when a story adds a branch before a privacy check, name the privacy case in its ACs.*

**R2 — Regenerating a stored Note resets user fields and orphans the old Study Set.** [adversarial + edge-case] `web/storage/db.ts:132-133` `put`s a fresh Note from `buildNoteRecord` (`web/core/noteRecord.ts:33-35`); 'Prøv igjen' on Notatoversikt (1.11, `Generating.tsx:127`) now also takes this path. Already in `deferred-work.md` (1.9) and `issues.md` (1.11), targeted at Epic 3. It becomes a real data-loss bug the moment Epic 2 writes `lastPractisedAt`/`conceptProgress`. *Disposition: fix in Epic 2 (move forward from Epic 3): merge user fields and delete the previous set in the same transaction (AD-21).*

**R3 — Browser runtime guard is looser than the contract and the storage schema.** [adversarial + edge-case] `web/api/studySet.ts:32-35`: `centralityRank`/`correctIndex` are `z.number()`, `options` has no length; `verifyStudySet.ts:64-66` checks only Quote and uniqueness. `web/storage/db.ts:53,61` read with stricter int schemas, so a malformed set saves and then reads as `note.missing` forever. The Proxy does enforce 4 options and `0 ≤ correct_index ≤ 3` (`proxy/app/rules.py:45`, `schemas.py:124`), so this needs a Proxy bug or a hand-edited Fixture. *Disposition: defer (cheap fix when Epic 2 touches Quiz Questions).*

**R4 — Storage read failures all render as "Fant ikke notatet".** [adversarial] `web/storage/db.ts:145-160` returns the same `FAILED` for missing, schema-invalid and IndexedDB failure; `web/app/notat/[noteHash]/page.tsx:35-39` maps all to `note.missing`. *Disposition: defer to Story 3.7 (Robust storage), which owns FR-21.*

**R5 — `err.noKey` before `/api/status` answers.** [edge-case] `web/core/gate.ts:12` treats a null status as "no key"; `web/app/page.tsx:94` checks the gate after extraction, and only `consent.declined` is auto-cleared (`page.tsx:53-55`). A file dropped in the first seconds after start (status retries up to 3 × 1 s) shows "Ingen API-nøkkel" with a key configured, and the error stays when status arrives. The architecture says live submit is *disabled* until status answers (epic-1-context › Status). Same race for 'Prøv igjen' on Notatoversikt after reload (`Generating.tsx:87`). *Disposition: fix now (small): wait for status or clear `err.noKey` when status reports a key.*

**R6 — Demo Mode stays on after picking a sample.** [adversarial + edge-case] `web/app/demo/page.tsx:71` persists `demoMode: true`. This is the specified behavior (epic-1-context › Demovelger; D-16), and the top-bar indicator shows it, but a consenting student with a key who tries the demo once gets `err.demoOnly` on every later upload. *Disposition: accept as specified; re-check in the Story 5.2 manual pass whether the indicator is noticed.*

**R7 — Demo POSTs skip the rate limit but still parse up to 8 MiB.** [adversarial + edge-case] `proxy/app/main.py:69-75`, `guards.py:47`. Local-only Proxy (127.0.0.1, origin allow-list), so the exposure is the student's own machine. *Disposition: accept (record).* Related: the limiter is keyed per Origin (`guards.py:57-66`), i.e. global for a single-user local app — consistent with README › Vern. *Accept.*

**R8 — Minor seams.** [edge-case/adversarial; (a) also verification-gap] (a) a Note ≤ 15 000 words but > 1 000 000 chars passes FR-3 in the browser and gets Proxy 400 → `err.generation` with a retry that always fails (`proxy/app/schemas.py:67-68` vs `web/core/passages.ts:11-12`); (b) Demovelger manifest failure has no retry (`web/app/demo/page.tsx:40-44`); (c) no `storage` event listener, so a second tab's Consent/Demo change is not reflected in the UI though requests read fresh settings (`AppSettings.tsx:53,76-80`); (d) regenerating an old Note after a `NORMALIZATION_VERSION` bump would fail the Quote Check (`web/core/overview.ts:31-32`; no bump has happened). *Disposition: defer, collect for Epic 3/5.*

### Process lessons (session logs)

**P1 — Tool layer rewrote `\u` escapes in the system prompt.** Story 1.6 shipped `proxy/app/prompts/system.md` with the `<`/`>`/`&` escapes collapsed into the characters themselves; found after merge and fixed in `6251765` (PR #7) with `PROMPT_VERSION` 2 and a binding test. Root cause per log `978-…-fiks-system-prompt-escapes.md`: the tool layer between agent and shell turns `\uXXXX` into the character before the command runs. This crossed a story boundary — it would have degraded the 1.8 Quote Check. *Prevention: record as a project-context pitfall (build such strings with `chr(92)`, verify raw bytes); the binding test now guards this file.*

**P2 — Hours are not logged against the milestone budget.** `epics.md` › Milestones requires comparing "done stories and hours spent with the budget" at each milestone; the `issues.md` item "logg timer brukt mot budsjett" is open, and no session log 969–986 records hours. Schedule-wise the epic is far ahead: all 14 stories done 2026-11-24 against M0 2026-11-26 and M1 2026-12-01. *Disposition: fix now if the budget is still meant to drive cuts; otherwise accept and drop the rule.*

**P3 — Docker rebuild needed for Proxy code changes.** `docker compose restart proxy` did not pick up the prompt fix; `--build` was needed (log 978). `issues.md` also has an open README item: the Proxy must be restarted after changing `OPENROUTER_API_KEY`/`OPENROUTER_MODEL`; README has no such note (grep "på nytt|omstart" finds only the test rebuild and rate-limit lines). *Disposition: fix now (README line).*
