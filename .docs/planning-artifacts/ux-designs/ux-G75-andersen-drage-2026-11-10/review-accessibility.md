# Accessibility review

## Verdict

**Not AA-ready. Fix before status final.** The text contrast table holds up: every ratio I recomputed matches within rounding. The spines then use that table to imply AA conformance, and it does not cover what will actually fail. The product's climax, the Quote highlight in the source panel (FR-12), is close to invisible in Lesesal (1.04:1 against the active Passage). The 'Dine notater' row nests two buttons inside a clickable row. That pattern trips axe `nested-interactive` (serious), which NFR-6 makes a test-suite gate. The global single-key shortcuts (Space / 1 / 2) have no off switch and no focus scoping. Focus after mark-and-advance, archive, quiz answer and the desktop reference jump is either unspecified or wrong. No surface defines headings, landmarks or page titles. Reflow is only promised at 360px, but WCAG 1.4.10 requires 320px.

## Findings

### Critical

- **[critical]** In Lesesal the Quote highlight is effectively invisible against the active Passage it sits in. `highlight` `#F3E3A3` on `passage-active` `#EFE6D2` is 1.04:1, and the 1px `highlight-ring` is 1.32:1. Kveldsmodus does slightly better: the fill is 1.89:1 (fails) and only the 1px ring (4.04:1) passes. This is the UJ-1 climax ("highlights the exact sentence"). A student with low vision, or anyone on a washed-out laptop panel, sees one beige block. Screen readers do not announce `<mark>` by default either, so the highlight conveys nothing non-visually. (§ DESIGN Colors/Quote highlight, Components › Quote highlight; EXPERIENCE Reference jump; SC 1.4.11, 1.4.1, 1.3.1) *Fix:* stop stacking the highlight on `passage-active`. Either drop the Passage tint while a Quote is highlighted, or use a darker highlight-ring (≥3:1 against the surrounding fill, e.g. a 2px `accent` underline/outline on the `<mark>`). Bracket the Quote with visually hidden "Sitat start" / "Sitat slutt" text, or reference the Quote via `aria-describedby` from the focused Passage. Add the pair to the contrast table.

- **[critical]** The Note row nests interactive controls. "Whole row is the hit area" plus "Row carries two own controls … separate Tab stops" means a link or `role="button"` row containing `<button>`s. That is invalid nesting (axe `nested-interactive`, serious). It fails the NFR-6 gate by construction, and screen readers flatten or swallow the inner controls. The Arkiv row inherits the same spec, and EXPERIENCE does not say what clicking an *archived* row does. (§ DESIGN Note row; EXPERIENCE Component Patterns › Note row, Interaction Primitives; SC 4.1.2, 1.3.1) *Fix:* make the title a real `<a>` to Notatoversikt and stretch its hit area with a `::after` overlay. Put the badge and 'Arkiver' as siblings in the DOM (not descendants of the link), raised with `position: relative; z-index`. Mark up the list as `<ul>`/`<li>`. State whether an Arkiv row opens anything; it should not.

### High

- **[high]** The global single-key shortcuts (Space, 1, 2, and "quiz option keys `[OPEN]`", likely A–D) have no way to turn them off or remap them, and they are not scoped to focus. They are suppressed only in text fields. In NVDA/JAWS browse mode the keys never reach the page. In focus mode, `1`/`2` collide with nothing visible but fire on stray keypresses, and speech-input users trigger them by dictating words. Space conflicts with native activation: with focus on "Kilde: P4", 'Forklar enklere' or 'Kunne det', a single Space both activates the focused control *and* flips or marks the card. Space also scrolls the page by default. Nothing says the shortcuts are suppressed while a dialog is open, or what Space does on an already revealed card. (§ EXPERIENCE Interaction Primitives › Keyboard, Flashcard, Quiz Question; SC 2.1.4, 2.1.1) *Fix:* scope the shortcuts so they fire only when focus is on the Flashcard region or its descendants and the focused element is not itself a button, link or checkbox. Add an Innstillinger toggle "Hurtigtaster (mellomrom, 1, 2)" (on by default for discoverability, off allowed). Suppress them while any dialog is open. Define Space on a revealed card as a no-op. Avoid A–D letter keys for quiz options; use 1–4 under the same scoping, or arrow keys within a radio group.

- **[high]** Focus after mark-and-advance is unspecified, so focus is lost. 'Kunne det' / 'Kunne det ikke' advances to the next card and removes the focused button. The same happens on flashcards → quiz, 'Neste spørsmål' / 'Se resultatet', and Resultat → 'Tilbake til oversikten'. Focus falls to `<body>` and the next Tab restarts at the top bar. A screen-reader user also gets no announcement that card 4 of 12 has loaded. (§ EXPERIENCE Flashcard, Quiz Question, Accessibility Floor; SC 2.4.3, 4.1.3) *Fix:* on every Item change, move focus to the new Item's heading (`h2` "Kort 4 av 12", `tabindex="-1"`). On screen changes, move it to the screen `h1`. Write the rule once in the Accessibility Floor.

- **[high]** The desktop reference jump has no way back. Focus moves to the target Passage, and the spine claims a "Shift+Tab path returns to the Item". It does not. Shift+Tab from a Passage goes to the previous focusable element in the source panel or the top bar, and Tab goes on to the study panel's *first* control, not the reference the user came from. On Resultat, with nine questions, the student has to tab back through the list after every jump. Mobile has 'Tilbake til kortet'; desktop has nothing. (§ EXPERIENCE Accessibility Floor, Reference jump; SC 2.4.3, 2.1.1) *Fix:* show a 'Tilbake til {kort 3 / spørsmål 4}' button at the top of the source panel after every jump, on desktop as well, and return focus to the exact reference that was activated. Let Esc while focus is in the Passage do the same.

- **[high]** No surface defines headings, landmarks or page titles. `headline` is an `[ASSUMPTION]` "not in mockups", and Round, Quiz, Resultat, Genererer and Demovelger have no stated `h1`. The source panel is not a landmark. Nothing says SPA route changes update `document.title` or move focus. Tab order "source panel before study panel" means every Round screen starts by reading or skipping 24 Passages before the card, and there is no skip link. (§ DESIGN Typography/Layout; EXPERIENCE IA, Accessibility Floor; SC 2.4.2, 1.3.1, 2.4.6, 2.4.1) *Fix:* add a per-surface table with `document.title` (e.g. "Runde · forelesning-7 · Torsas læringsassistent"), the `h1` text, and landmarks: `header` (top bar), `main` (study panel), and `<aside aria-label="Kilde: forelesning-7.pdf">` (source panel). Add a skip link "Gå til kortet / hovedinnhold". Put the study panel first in DOM and tab order and keep the source panel visually left. The current "source before study" assumption is backwards for this product.

- **[high]** The cycling importance badge is undiscoverable, poorly announced and disorienting. Visually it matches the read-only concept chip exactly (`surface`, `line` border, pill, `chip` type), and its only boundary is `line` at 1.34:1, which breaks DESIGN's own rule that `line` must never be the sole boundary of an interactive control. Its accessible name, "Viktighet {n}, trykk for å endre", puts usage instructions in the name and does not say what 1 means. The *visible* "1/2/3" never says that 1 = most important. Each activation re-sorts the list immediately, so the focused row jumps position. If the framework remounts the row, focus is lost. Getting from 2 to 1 takes two presses and two re-sorts. Nothing announces the new value or the new position. (§ DESIGN Importance badge; EXPERIENCE Importance badge, Note Lifecycle › Order; SC 1.4.11, 4.1.2, 4.1.3, 2.4.3, 3.3.2) *Fix:* replace the cycle with a menu button or native `<select>` named "Viktighet for {tittel}", with options "1 – viktigst / 2 – middels / 3 – minst". Use an `ink-muted` border and a chevron so it looks editable. Defer the re-sort until focus leaves the list, or keep focus on the moved control and announce "{tittel} flyttet til plass 1" in a `role="status"` region.

- **[high]** Reflow is promised at 360px, but 1.4.10 requires 320 CSS px (1280px at 400% zoom). The top bar has brand, Note name, "Klar for eksamen 63 %", the gap note, the theme toggle and 'Innstillinger', and its mobile form is only "condensed `[ASSUMPTION]`". `card-front` is 26px Georgia, and Norwegian compound words ("eksamensforberedelse", "normaliseringsregler") will overflow a 288px content box. Full-width dialogs with the 'Les mer' expansion need internal scrolling at 200% zoom on a 320px height. (§ DESIGN Layout & Spacing; EXPERIENCE Responsive & Platform; SC 1.4.10, 1.4.4; PRD NFR-7) *Fix:* make 320px the floor in Responsive & Platform. Specify the condensed top bar (brand link + overflow menu holding Readiness and the gap note, theme, Innstillinger). Use `overflow-wrap: anywhere; hyphens: auto` with a correct `lang`. Give dialogs `max-height: 100dvh` with internal scroll. Express font tokens in rem.

- **[high]** Archiving removes the row with no confirmation, no undo and no focus target. Focus sits on 'Arkiver', the row disappears, and focus goes to `<body>`. A screen-reader user hears nothing. A mis-tap is likely because 'Arkiver' is a "small button" next to a small badge, and it silently hides a Note. Restore and permanent delete in Arkiv have the same focus problem. (§ EXPERIENCE Note Lifecycle, Confirmation policy, Flow 4; SC 2.4.3, 4.1.3) *Fix:* after archive, restore or delete, move focus to the next row (or the previous one, or the list heading if it is empty). Announce "{tittel} er arkivert" in `role="status"` with an 'Angre' action that stays until the next action, not on a timer.

### Medium

- **[medium]** Quiz answering leaves focus undefined. Selecting an option "answers" and shows inline feedback. If the options become `disabled`, the focused option loses focus. The `aria-live="polite"` feedback can be cut off or queued behind a focus change. The ✓/✗ glyphs are read as "check mark" / "multiplication x" or skipped. (§ DESIGN Quiz Question; EXPERIENCE Quiz Question, Accessibility Floor; SC 2.4.3, 4.1.3, 1.1.1) *Fix:* mark answered options `aria-disabled="true"` (keep them focusable) and move focus to the feedback heading ("Riktig." / "Det var nok feil, rett svar er C."). Add visually hidden text on options: "Ditt svar, feil" / "Riktig svar". Group the options as a `radiogroup` or a list of buttons labelled with the stem.

- **[medium]** The "dedicated error role" cannot be told apart from mastery 'usikker'. `error-bg` vs `mastery-shaky-bg` is 1.01:1 (light) and `error-fg` vs `shaky-fg` is 1.08:1. The spine claims they are distinct roles but the colors are effectively identical, and "no red alarm styling" removes any other cue. (§ DESIGN Colors › error, Components › Error message; SC 1.4.1, 3.3.1) *Fix:* give errors a non-color identifier, such as a leading icon with `aria-hidden` plus a visually hidden or visible "Feil:" prefix, and a border or rule in `error-fg`. Render errors with `role="alert"` (blocking) or `role="status"`, and tie field errors to the drop zone or text area via `aria-describedby` + `aria-invalid`.

- **[medium]** The keyboard hint is illegible inside a primary button. A `kbd-hint` in `ink-muted` on an `accent` fill is 1.30:1 (light) and 1.35:1 (dark), at 11px. If 'Snu kortet' (Space) or any marked button is primary, the hint fails 1.4.3. It is informative text, not decoration, even when hidden from AT. (§ DESIGN Button, kbd-hint; SC 1.4.3) *Fix:* inside primary buttons, render the hint in `on-accent` at 80–100% with an `on-accent` border. Add the pair to the contrast table.

- **[medium]** Note content has no language markup. Generated content "follows the Note's language", but `lang` on Note content is `[OPEN]`. An English lecture note (common in IBE160) will be read in a Norwegian voice, and hyphenation (above) depends on `lang`. (§ EXPERIENCE Foundation, Accessibility Floor; SC 3.1.2) *Fix:* store a detected language per Note (generation can return it; fall back to `nb`). Set `lang` on the source panel, card front and back, Quote blocks, Summary Points and Quiz stems/options. UI chrome stays `lang="nb"`.

- **[medium]** Mobile tabs and the return toast are under-specified. Neither spine mentions `role="tablist"`/`tab`/`tabpanel`, `aria-selected`, arrow-key navigation, or hiding the inactive panel from AT. The return toast sits at the top of the Kilde tab, *above* the Passage that receives focus, so a screen-reader user never encounters it. The word "toast" invites an auto-dismiss timer. Its label "Tilbake til kortet" is wrong on Quiz and Resultat. (§ DESIGN Tabs, Return toast; EXPERIENCE Tabs, Return toast; SC 4.1.2, 2.4.3, 2.2.1) *Fix:* use the ARIA tabs pattern with manual activation. Make the return control persistent (no timer) and reachable as the next Tab stop after the focused Passage, or announce it via the Passage's `aria-describedby`. Make the label context-aware: 'Tilbake til kortet / spørsmålet / resultatet'.

- **[medium]** The active Passage is a tint only. `passage-active` vs `surface-source` is 1.09:1 / 1.11:1. Once the student scrolls, nothing shows which Passage the reference targeted except a near-invisible fill. (§ DESIGN Passage; SC 1.4.11, 1.4.1) *Fix:* add a 3px `accent` left rule (7:1+) to the active Passage, matching the Quote-block rule.

- **[medium]** The scrollable source panel is not keyboard reachable as written. It "scrolls independently", but Passages are only programmatically focusable (`tabindex="-1"`). With no focusable content, a keyboard user cannot scroll it (axe `scrollable-region-focusable`, serious). The `focus-offset` outline on a focused Passage will also be clipped by the panel's `overflow`. (§ EXPERIENCE Source panel, Passage; SC 2.1.1, 2.4.7) *Fix:* give the panel `tabindex="0"`, `role="region"` and a label. Use an inset focus ring (negative offset) for Passages and other elements inside scroll containers.

- **[medium]** Generation progress is a lie to assistive technology, and its live region is unspecified. A "determinate-looking bar" with no real progress will either expose fake `aria-valuenow` or none at all. The status steps are `[ASSUMPTION]` and their announcement cadence is undefined. Nothing says where focus goes on the 90s timeout error or on success (route change to Notatoversikt). The 90s server timeout is not a 2.2.1 user time limit, so it does not need to be adjustable. The wait still needs a 'Avbryt' control, though: the upload is disabled and there is no exit. (§ DESIGN Generation progress; EXPERIENCE Generating, Generation failed; SC 4.1.3, 4.1.2, 2.4.3) *Fix:* use an indeterminate `role="progressbar"` with `aria-label="Lager kort og quiz"` and no `aria-valuenow`. Announce each status step once via `role="status"`. On error, focus the error heading. On success, focus the Notatoversikt `h1`. Add 'Avbryt'.

- **[medium]** Dialog focus details are missing. The delete dialog's initial focus is unspecified; for a destructive action it must be 'Avbryt', not 'Slett'. No `aria-labelledby`/`aria-describedby`. The Consent gate cannot be dismissed (fine), but nothing says whether 'Les mer' is an in-dialog disclosure (`aria-expanded`) or navigation. Navigation would break the "one level" modal rule and the focus trap. The 'Ikke spør igjen' checkbox needs a real label. (§ EXPERIENCE Dialog, Consent & Privacy, delete.confirm; SC 2.4.3, 4.1.2, 3.3.2) *Fix:* use native `<dialog>` with `showModal()`, a title as `h2` referenced by `aria-labelledby`, and the body via `aria-describedby`. Initial focus goes to 'Avbryt' in the delete dialog and to the dialog heading or first paragraph in Consent. Make 'Les mer' an in-place disclosure. Use `<input type="checkbox">` with a `<label>` for 'Ikke spør igjen'.

- **[medium]** Forced-colors / Windows High Contrast is ignored. `box-shadow` is the highlight ring and it is dropped. Background fills are overridden: `<mark>`, `passage-active`, mastery chips, the progress fill and the quiz correct/wrong state. The highlight, active Passage, progress bar and quiz state all vanish. (§ DESIGN Quote highlight, Round progress, Quiz Question; SC 1.4.11, 1.4.1) *Fix:* add `@media (forced-colors: active)` rules. Use `outline`/`border` (not `box-shadow`) for the ring, `Mark`/`MarkText` system colors for the Quote, `Highlight` for the progress fill, and borders on chips.

- **[medium]** Targets are small next to a destructive neighbour. The 44 × 44px mobile target is only an `[ASSUMPTION]`. The badge (12px pill), the "small" 'Arkiver' button and the inline 13px "Kilde: P4" links are drawn well below it, and the badge and 'Arkiver' sit side by side. 2.5.5 is AAA in WCAG 2.1, but the spine set its own bar and the components do not meet it. (§ DESIGN Note row, Importance badge, Source reference; EXPERIENCE Accessibility Floor; SC 2.5.5 [AAA], aligns with 2.2 2.5.8) *Fix:* commit to a 44px hit area (padding or pseudo-element) for the badge, 'Arkiver', the theme toggle and the references. Keep at least 8px between the badge and 'Arkiver', or move 'Arkiver' into a row overflow menu.

- **[medium]** Error messages are missing suggestions and programmatic association. err.noText ("Fant ingen tekst i filen.") gives no next step, which contradicts the Voice rule "say what is wrong, then what to do". err.generation hides the cause. File validation is asynchronous (PDF parse), so the error appears after the file picker closes and must be announced. The text-area submit label is `[OPEN]` in Component Patterns but "Lag kort og quiz" in Microcopy, which is inconsistent. (§ EXPERIENCE Microcopy, Text area, Input rejected; SC 3.3.1, 3.3.3, 4.1.3, 3.3.2) *Fix:* change err.noText to "Fant ingen tekst i filen. Prøv en annen fil, eller lim inn teksten." Announce async validation results via `role="alert"` and move focus to the message. Resolve the submit label in one place. Give the drop zone a native `<input type="file">` with a `<label>` and `aria-describedby` pointing at the accepted-types line.

### Low

- **[low]** The progress bar track (`line`) is 1.27–1.43:1 against its surroundings, so the bar's total extent cannot be perceived. The text "Kort 3 av 12" provides the information, so this does not fail AA, but the bar should be `aria-hidden` or a labelled `progressbar`, not both. (§ DESIGN Round progress; SC 1.4.11) *Fix:* use an `ink-muted` 1px track border or make the bar decorative and `aria-hidden`.
- **[low]** Quiz options and secondary buttons rely on the `line` border (1.34:1). Text-labelled buttons pass 1.4.11 on their text, but a full-width option list on a near-white card reads as plain text rows, especially in light mode. (§ DESIGN Quiz Question, Button; SC 1.4.11 advisory) *Fix:* use an `ink-muted` border on quiz options (5.7:1), matching inputs.
- **[low]** The theme toggle's semantics are muddled. The "accessible name states the target mode" while the glyph is "sun (light) / moon (dark)", and it is ambiguous whether the glyph shows the current or the target mode. (§ DESIGN Theme toggle; EXPERIENCE Theme toggle; SC 4.1.2, 2.5.3) *Fix:* use a fixed name "Mørk modus" with `aria-pressed`, and make the glyph show the current state.
- **[low]** Pending buttons are `disabled`, which drops focus on 'Lag kort og quiz' and 'Forklar enklere' mid-action. (§ EXPERIENCE Button, Explain Simpler; SC 2.4.3, 4.1.3) *Fix:* use `aria-disabled="true"` plus `aria-busy` on the result region, and announce "Lager enklere forklaring …" via `role="status"`.
- **[low]** "Klar: –" (UJ-1 step 5) is read as "minus" or nothing, and "Kilde: P4" is cryptic out of context on Resultat, where several references repeat. (§ EXPERIENCE UJ-1, Source reference; SC 2.4.4, 1.1.1) *Fix:* use visually hidden text "ingen poengsum ennå". Give references an accessible name such as "Kilde: avsnitt 4, vis i notatet".
- **[low]** The one-time storage warning and the "Progresjon lagres ikke" notice have no component or persistence spec. If either is built as a timed toast, it fails 2.2.1 / 4.1.3. (§ EXPERIENCE State Patterns; SC 2.2.1, 4.1.3) *Fix:* use a persistent banner with `role="status"`, dismissed by the user.
- **[low]** Motion: only the reference scroll respects `prefers-reduced-motion`. "Snu kortet" suggests a flip animation, and the theme switch may transition. (§ EXPERIENCE Interaction Primitives; SC 2.3.3 [AAA], good practice) *Fix:* use a global reduced-motion rule that removes the flip, cross-fades and smooth scroll.
- **[low]** Text spacing is untested against pills and fixed-height chrome (`rounded.full` chips, the 6px progress bar, the kbd-hint box), and px font tokens ignore the user's default font size. (§ DESIGN tokens; SC 1.4.12, 1.4.4) *Fix:* use rem tokens and no fixed heights on text containers. Add a 1.4.12 bookmarklet pass to the manual checklist.
- **[low]** Accidental marks are permanent. 1/2 saves immediately and changes Mastery, with no undo. This is not an AA failure (3.3.4 does not apply), but it compounds the shortcut finding for tremor and switch users. (§ EXPERIENCE Flashcard; SC 2.1.4 related) *Fix:* add 'Angre' for the last mark, available until the next card is marked.
